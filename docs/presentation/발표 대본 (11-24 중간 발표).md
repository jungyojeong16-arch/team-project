## 3. 프로젝트 구현 진도 (3분)

### 3.1 개발 진행 방식
**[화면] 3.1 굵은 글씨 한 줄 → 3.1.1 접기 펼치기**

> 개발은 교수님께서 알려 주신 순서대로 진행했습니다.
> **기능을 프로그램 목록으로 나누고, 프로그램마다 PRD를 쓰고, PRD를 단계별 프롬프트로 만들어 AI와 코딩한 다음, PRD의 완료 기준으로 저희가 직접 확인했습니다.**
> 실제로 AI에게 보낸 프롬프트와 결과는 **프로그램별로 GitHub에 기록**했습니다. 기록마다 '확인'과 '수정 요청' 칸이 있어서, 저희가 결과를 검사하고 다시 고치게 한 과정이 남아 있습니다.
> 그리고 세 명이 각자 AI를 쓰다 보니 AI끼리는 서로의 대화를 모릅니다. 그래서 **공용 작업 일지를 만들어 누가 무엇을 했는지 남기고, 작업 전에 먼저 읽도록** 했습니다.
(3.1.1 접기 닫기)

### 3.4 실행 결과
**[화면] 3.4 글머리 3줄 → 접기 ②, ③, ④ 차례로 펼쳤다 닫기**

> 실제 작품 200편으로 **홈 화면의 TOP 10과 통합 랭킹 1~10위가 같은지** 직접 확인했습니다.
> 화면은 기능별로 접어 두었습니다.
- ② 펼치고 > **홈 화면입니다. 지금 시간대와 설문 답에 맞춘 오늘의 추천이 나오고, 아래에 맞춤 추천과 통합 랭킹 TOP 10이 있습니다.** 맞춤 추천 화면에서는 작품마다 추천 이유가 한 줄씩 붙습니다.
- ③ 펼치고 > **'스파이더맨'을 검색하면 두 글자부터 결과가 나오고, 누르면 상세 팝업에서 회원 평점과 내 세대 평균을 보고, OTT 버튼으로 그 OTT에 바로 갈 수 있습니다.**
- ④ 펼치고 > **통합 랭킹 TOP 100과, 20대·40대처럼 연령대별로 순위가 달라지는 세대별 랭킹입니다.**

### 프론트엔드 (Next.js · React · TypeScript, 폴더 `app/`)

## 부록 C. 예상 질문과 답

**Q. AI가 만든 것 말고 사람이 한 일은?**
> AI는 코드를 쓰는 도구로 썼고, 무엇을 만들지와 결과가 맞는지는 저희가 정하고 확인했습니다. 서비스 기획, 프로그램 목록, Figma 화면, DB 설계, PRD의 완료 기준은 저희가 정했고, AI 결과를 직접 실행해 기준대로 검사하고 틀린 것은 다시 고치게 했습니다. 예를 들어 홈 TOP 10과 랭킹 1~10위를 직접 비교했고, 설문 뒤 오류가 났을 때 DB 변경이 반영되지 않은 원인을 찾아 해결했습니다. 그 과정이 프롬프트 기록의 '확인', '수정 요청' 칸과 작업 일지에 남아 있습니다.
(실제로 하지 않은 것은 빼고 말하기)

**Q. 바로가기를 누르면 작품 페이지로 바로 가나요?**
> OTT들이 작품별 주소를 외부에 공개하지 않아서, 각 OTT의 작품 검색 결과로 연결했습니다. 티빙, 웨이브, 왓챠는 검색 결과에 바로 나오고, 넷플릭스와 쿠팡플레이는 로그인하면 이어집니다. 디즈니+는 주소를 고치는 중입니다.

**Q. AI 추천은 어떻게 하나요? 추천 이유는 AI가 쓰나요?**
> 설문의 좋아하는·싫어하는 장르, 기억에 남는 작품, 같은 세대의 평점, 지금 시간대의 상황을 점수로 합쳐 순위를 냅니다. 추천 이유는 정해 둔 문장 틀에 취향과 상황을 넣어 만듭니다.

**Q. 평점 데이터가 많지 않을 텐데요?**
> 시연용 가상 회원 60명의 평점을 만들어 쓰고, 화면에 '시연용 가상 평점이 포함되어 있어요'라고 표시합니다. 배포 후 실제 회원 평점이 쌓이면 그대로 반영됩니다.

**Q. 세대별 평점은 회원 나이로 묶나요?**
> 아니요. 해가 바뀌면 회원 연령대가 바뀌어 예전 평가가 다른 세대로 옮겨 가기 때문에, 평점을 남길 때의 연령대를 따로 저장해서 묶습니다.

**Q. 남은 기간에 다 할 수 있나요?**
> 평가와 좋아요는 테이블과 저장 규칙을 이미 만들어 둬서 화면과 연결하는 일이 중심입니다. 배포가 늦어지면 노트북으로 시연할 수 있게 시연 영상도 미리 녹화해 두겠습니다.

**Q. 답을 모르겠을 때**
> "정확히 확인해서 다음 시간에 말씀드리겠습니다."
