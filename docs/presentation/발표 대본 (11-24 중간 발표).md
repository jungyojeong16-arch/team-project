## 1. 프로젝트 개발 환경 (2분)

### 1.1 개발 환경 요약
**[화면] 1.1 표**

> 먼저 개발 환경입니다.
> **화면은 Next.js와 React로, 언어는 TypeScript를 썼습니다.**
> **서버는 Python의 Django와 Django REST Framework로 만들었고, DB는 MariaDB를 씁니다.**
> 지금은 각자 PC에서 프론트는 3000번, 백엔드는 8000번 포트로 실행하고 있고, **11월 28일, 29일에 AWS EC2와 RDS로 배포할 예정입니다.**
> 화면은 Figma로 먼저 16개를 설계하고, 그 디자인과 똑같이 맞추는 것을 기준으로 개발했습니다.
> 그리고 코드는 **Claude Code를 이용한 AI 바이브 코딩**으로 작성했습니다. 이 방식은 뒤에서 자세히 말씀드리겠습니다.

### 1.2 ~ 1.3 도구 · 오픈소스
**[화면] 1.2 → 1.3 표 (천천히 스크롤만)**

> 협업은 GitHub와 노션으로 했고, DB 설계는 draw.io, DB 내용 확인은 HeidiSQL로 했습니다.
> 오픈소스는 프론트엔드에 Tailwind CSS와 lucide 아이콘, 백엔드에 Django REST Framework와 MariaDB 연결용 mysqlclient 등을 썼습니다.

### 1.4 외부 데이터
**[화면] 1.4**

> 작품 정보는 **TMDB라는 영화 정보 API에서 제목, 포스터, 장르, 그리고 한국에서 볼 수 있는 OTT 정보를 받아 왔고, 지금 200편이 들어 있습니다.**
> 작품을 고르면 그 작품이 있는 OTT로 바로 이동하는 바로가기도 만들었습니다.

### 1.5 API 목록 · ERD
**[화면] 1.5 표 → ERD 그림**

> **API는 19개를 만들었고**, 표 오른쪽에 어느 프로그램에서 쓰는지 번호를 적어 두었습니다.
> **DB는 테이블 14개입니다.** 파란색은 회원, 작품 같은 기본 테이블이고, 초록색은 평점, 좋아요처럼 회원과 작품을 잇는 테이블입니다.
> (ERD 질문이 나오면: 세대별 평점 때문에 평점 테이블에 '평가할 당시 연령대'를 따로 저장한 점을 말하기)

## 3. 프로젝트 구현 진도 (3분)

### 3.1 개발 진행 방식
**[화면] 3.1**

> 개발은 교수님께서 알려 주신 순서대로 진행했습니다.
> **기능을 프로그램 목록으로 나누고, 프로그램마다 PRD를 쓰고, PRD를 단계별 프롬프트로 만들어 AI와 코딩한 다음, PRD의 완료 기준으로 저희가 직접 확인했습니다.**
> 세 명이 각자 AI를 쓰다 보니 AI끼리는 서로의 대화를 모릅니다. 실제로 같은 기능을 두 번 만든 적이 있어서, **공용 작업 일지를 만들어 누가 무엇을 했는지 남기고 작업 전에 먼저 읽도록** 했습니다.

### 3.2 주차별 보고서
**[화면] 3.2 목록**

> 주차별 보고서는 2주차부터 11주차까지 노션에 정리했습니다.
> 3주차에 주제를 OTT 큐레이션으로 바꿨고, 6주차에 Figma와 ERD 설계, **10주차부터 실제 구현을 시작해서 지난주인 11주차에 랭킹, 추천, 설문, 작품 데이터까지 진행했습니다.**

### 3.3 프로그램 PRD
**[화면] PRD PDF 열기 → 6-1 통합 랭킹 페이지**

> PRD는 15개를 썼고, 한 파일로 모은 PDF가 64쪽입니다. 하나만 예로 보여 드리겠습니다.
> 이것은 **6-1 통합 랭킹 PRD**입니다. 목적, 기능, 데이터와 API, 그리고 맨 아래에 **완료 기준**과 **AI에게 보낸 단계별 프롬프트**가 있습니다.
> 예를 들어 통합 랭킹 점수는 **TMDB 인기도 70%, 회원 평점 30%** 로 정했고, 평가가 한두 개뿐인 작품이 1위가 되지 않도록 평균을 보정했습니다.
> 완료 기준에 적힌 대로 순위 100개가 저장되는지, 날짜를 바꾸면 순위 변동이 보이는지 하나씩 확인했습니다.

### 3.4 실행 결과
**[화면] 3.4 → 캡처 사진들 빠르게 스크롤**

> 확인 결과입니다. **자동 테스트 81개가 모두 통과**했고,
> 실제 작품 200편으로 **홈 화면의 TOP 10과 통합 랭킹 1~10위가 같은지, 세대별 랭킹 1~3위가 SQL로 직접 계산한 값과 같은지**도 확인했습니다.

## 4. 시연 (4분)
**[화면] localhost:3000 탭 (로그인한 상태)**

> 이제 실제 사이트를 보여 드리겠습니다.

1. **홈**
   > 로그인하면 홈 화면이 나옵니다. 위에 지금 시간대와 제 연령대, 직업에 맞춘 문구가 있고, **설문에서 고른 취향으로 오늘의 추천 작품**을 보여 줍니다.
2. **[바로 보기] 클릭 → OTT 새 탭**
   > 바로 보기를 누르면 **그 작품이 있는 OTT가 새 탭으로 열립니다.** OTT들이 작품별 주소를 공개하지 않아서, 각 OTT의 작품 검색 결과로 연결했습니다.
   (새 탭 닫고 돌아오기)
3. **통합 랭킹 → 영화 + 넷플릭스 필터 → 펼치기**
   > 상단의 통합 랭킹입니다. 여러 OTT 작품을 하나의 TOP 100으로 보여 주고, 지난 집계보다 오르고 내린 것도 표시합니다. 영화, 넷플릭스로 거르면 **조건에 맞는 작품만 1위부터 다시 순위를 매깁니다.**
4. **세대별 랭킹 → 20대 → 40대**
   > 세대별 랭킹입니다. 20대에서 40대로 바꾸면 **순위가 완전히 달라지는 것**을 볼 수 있습니다.
5. **상단 검색 → 작품 클릭 → 상세 팝업**
   > 검색창에 두 글자 이상 넣으면 작품이 나오고, 누르면 상세 팝업에서 **세대별 평균 평점을 비교**할 수 있습니다.
6. **(시간 남으면) 맞춤 추천 → 상황 필터**
   > 맞춤 추천에서는 '혼자 보는 밤', '퇴근 후' 같은 상황별로 TOP 50을 볼 수 있습니다.

## 예상 질문과 답 (외워 두기)

**Q. 바로가기를 누르면 작품 페이지로 바로 가나요?**
> 넷플릭스 같은 OTT들이 작품별 주소를 외부에 공개하지 않아서, 각 OTT의 작품 검색 결과로 연결했습니다. 티빙, 웨이브, 왓챠는 검색 결과에 바로 나오고, 넷플릭스와 쿠팡플레이는 로그인하면 이어집니다. 디즈니+는 주소를 고치는 중입니다.

**Q. AI 추천은 어떻게 하나요?**
> 설문에서 고른 좋아하는 장르와 싫어하는 장르, 기억에 남는 작품, 같은 연령대의 평점, 그리고 지금 시간대에 맞는 상황을 점수로 합쳐서 순위를 냅니다. 이미 평가했거나 본 작품은 빼고 추천합니다.

**Q. 추천 이유 문장은 AI가 만드나요?**
> 지금은 정해 둔 문장 틀에 취향과 상황을 넣어 만듭니다. 생성형 AI API는 비용과 키 관리 문제가 있어서 팀에서 정한 뒤 붙일 예정입니다.

**Q. 평점 데이터가 많지 않을 텐데요?**
> 시연용 가상 회원 60명의 평점을 만들어 쓰고, 화면 아래에 '시연용 가상 평점이 포함되어 있어요'라고 표시합니다.

**Q. 세대별 평점은 회원 나이로 묶나요?**
> 아니요. 해가 바뀌면 회원 연령대가 바뀌어서 예전 평가가 다른 세대로 옮겨 가기 때문에, 평점을 남길 때의 연령대를 따로 저장해서 묶습니다.

**Q. AI가 다 만든 것 아닌가요? 팀원이 한 일은?**
> 기능을 프로그램 목록과 PRD로 정한 것, 단계별로 요청한 것, 완료 기준으로 직접 확인하고 틀린 부분을 고쳐 달라고 한 것은 저희가 했습니다. 그 과정이 GitHub의 프롬프트 기록과 작업 일지에 남아 있습니다.

**Q. 남은 기간에 다 할 수 있나요?**
> 평가와 좋아요는 테이블과 저장 기능을 이미 만들어 둬서 화면과 연결만 하면 됩니다. 배포가 늦어지면 노트북에서 시연할 수 있게 시연 영상도 미리 녹화해 두겠습니다.
