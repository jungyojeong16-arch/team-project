## 0-2 공통 규칙 (초안 — 회의에서 확정)

### 폴더 · 파일
| 위치 | 넣는 것 | 주인 |
|---|---|---|
| `app/_components/` | 여러 화면이 같이 쓰는 부품 (0-3) | 정재준 (고칠 때 단톡방에 먼저 알림) |
| `app/_lib/` | API 부르는 함수 — 기능별 파일 (`account.ts`, `ranking.ts`, `recommend.ts` …) | 각 기능 담당 |
| `app/<기능>/page.tsx` | 화면 | 각 기능 담당 |
| `backend/core/models.py` | 테이블 | **정준교만 수정** (다른 사람은 요청) |
| `backend/core/views.py`, `urls.py`, `serializers.py`, `tests.py` | API | 각 담당이 자기 기능 부분만, 기능별 구역 주석으로 나눔 |

### API
- 주소는 `/api/v1/` 로 시작, 이름은 영어 소문자·복수형 (`/contents/`, `/rankings/`)
- 로그인 필요한 API는 헤더 `Authorization: Token <키>`, 없으면 401
- 목록은 `offset`·`limit` (기본 20)
- 오류는 `{"칸이름": ["한국어 안내"]}` 모양 (지금 회원가입 API와 같음)
- 평균·개수 등 계산값은 저장하지 않고 조회할 때 계산 (ERD 원칙 ⑤)

### 이름 · 문구
- 화면 문구는 Figma 그대로. Figma의 "샘플/예시 데이터" 문구는 진짜 데이터로 바뀌면 지움
- 장르·OTT·상황 이름은 DB 기본 데이터와 똑같이 (예: `디즈니+`, `혼자 보는 밤`)

### GitHub · 진행
- 바이브 코딩 결과는 기능 PRD의 **6. 완료 기준**을 통과한 뒤 GitHub에 올림
- 같은 파일을 두 사람이 동시에 고치지 않음 → 공통 파일(`_components`, `models.py`)은 단톡방에 먼저 알리기
- 올린 뒤 목록표의 상태를 ✅로 바꾸기
- `.env`, 비밀번호, API 키는 절대 올리지 않음

**완료 기준**: 3명이 이 규칙을 읽고 동의, 바뀐 점을 이 문서에 반영.
