## 1. 목적
설문 이후에 회원이 실제로 보고·좋아한 작품(최근 관심사)을 추천에 반영할지 **회원에게 먼저 묻고**, 동의할 때만 추천을 바꾼다.

## 2. 사용자 이야기
- 회원으로서, 요즘 자주 본 장르가 추천에 반영되면 좋겠다.
- 회원으로서, 내 동의 없이 추천이 갑자기 바뀌는 건 싫다.

## 3. 기능 요구사항
| ID | 내용 | 구분 |
|---|---|---|
| FR1 | 홈에서 조건(아래)을 만족하면 팝업: "최근 관심사를 맞춤 추천에 반영할까요?" + 최근 관심 작품 1개(포스터·정보·OTT) | 필수 |
| FR2 | 안내 문구: "동의하시면 최근 보거나 찾아본 작품의 관심사를 다음 맞춤 추천에 함께 반영할게요", "기존 선호·비선호 설정은 그대로 유지돼요", "동의하기 전에는 추천을 변경하지 않아요" | 필수 |
| FR3 | [반영해서 추천 바꾸기] → 최근 활동 점수를 더해 추천 새로 만들기 → 홈의 오늘의 추천이 바뀜 | 필수 |
| FR4 | [지금 추천 유지] · 닫기 → 아무것도 바꾸지 않고 오늘은 다시 묻지 않음 | 필수 |

### 팝업을 띄우는 조건
- 마지막으로 추천을 만든 뒤 **새 활동이 3개 이상** (바로 보기 기록 direct, 좋아요, 4.0점 이상 평점 — 최근 14일)
- 오늘 이미 물어봤으면 띄우지 않음 (브라우저에 날짜 저장)
- 7-2 피드백 팝업이 떠야 하면 그것을 먼저 (같은 방문에 팝업 1개만)

### 최근 활동 점수 (7-1 점수에 더함)
- 최근 14일 활동 작품들의 장르와 겹치면 장르 1개당 +2
- **설문의 비선호 장르 제외 규칙은 그대로** (FR2 약속)

## 4. 데이터 · API
| 방식 | 주소 | 내용 |
|---|---|---|
| GET | `/api/v1/me/interest-check/` 🔒 | `{should_ask, sample_content, new_activity_count}` |
| POST | `/api/v1/me/interest-apply/` 🔒 | 최근 활동 반영해서 추천 새로 만들기 → 새 추천 1위 |

- 새 테이블 없이 기존 기록(`watch_history`, `content_like`, `rating`, `recommendation.recommended_at`)으로 계산한다.

## 5. 규칙 · 예외
- 동의하지 않으면 서버에 아무것도 저장하지 않는다.
- 최근 활동 작품이 모두 비선호 장르면 팝업을 띄우지 않는다.

## 6. 완료 기준
- [ ] 좋아요 3개를 누른 뒤 홈 새로고침 → 팝업
- [ ] [지금 추천 유지] → 오늘의 추천 그대로, 다시 새로고침해도 팝업 없음
- [ ] (다음 날로 바꿔) [반영해서 추천 바꾸기] → `recommendation`에 새 묶음, 홈 추천이 바뀜
- [ ] 반영 후에도 비선호 장르 작품은 추천에 없다
- [ ] 화면이 Figma 224:5091 과 같다

## 7. 범위 밖
